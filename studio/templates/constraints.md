# Constraints (owner fills this in, optional)

Used by the Scoping Analyst and the Studio Lead to check a scope against what is actually possible. Copy it into the product folder as `projects/<product>/constraints.md`. Do not guess; leave unknown fields as TBD.

| Field | Value |
|---|---|
| Time available (per week, and until which date) | |
| People and roles available | |
| Fixed dates (launch, review, event) | |
| Platforms in bounds (web, iOS, Android) | |
| Work included (research, UX, brand, design system, screens, prototype, documentation) | |
| Limits (number of screens or flows, revisions) | |
| Out of bounds (what will not be done) | |
| Tools and licences available (Figma seat, fonts, stock) | |

## When the scope does not fit
- Reduce scope / phase the work / extend the time. Write which one the owner prefers and who decides.
